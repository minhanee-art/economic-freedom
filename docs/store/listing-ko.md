# 스토어 등록정보 초안 (한국어)

> 초안입니다. 앱 이름 '가족연금계획'은 가제입니다.
> 작성 기준: `mobile/` 앱에 **실제로 있는 화면**과 `src/app` 웹 서비스(2026-11-27 main 코드 재확인). 모바일 앱은 로그인·가입, 홈·자산·배당·연금·설정 탭, 계좌 전환, 매수 기록·배당 수령 기록 입력(두 기록 모두 개별 삭제 가능), 연금 설계 요약(읽기 전용), 비밀번호 변경, 계정 삭제를 지원합니다. 보유 종목 편집·은퇴 목표·연금 소득원 입력은 웹 서비스에서 합니다. 매수 기록 삭제는 PR #36으로 모바일에 들어왔습니다(최근 기록의 '삭제' 버튼 + 확인 창, `mobile/src/app/record-purchase.tsx`). 단, 이후 같은 종목 매도 기록이 있는 등 보유 수량·원가를 정확히 되돌릴 수 없으면 서버가 삭제를 거절합니다(`src/app/api/purchases/[id]/route.ts`). 아래 설명은 이 사실을 숨기지 않도록 썼습니다.
> 글자 수 제한 출처: Google Play — https://support.google.com/googleplay/android-developer/answer/9859152 (앱 이름 30자, 짧은 설명 80자, 자세한 설명 4,000자, 확인일 2026-11-27) / App Store — https://developer.apple.com/help/app-store-connect/reference/app-information (이름 30자, 부제 30자, 확인일 2026-11-27. 키워드 100바이트·설명 한도는 해당 페이지에 없어 **미확인(기억 기준)**).

## 2. 짧은 설명 (Play, 80자 이내)

```
내가 입력한 연금·배당 보유 내역을 모아 보고, 은퇴 현금흐름 목표와 비교하는 기록 앱
```
(공백 포함 약 45자)

- 피해야 할 표현: 수익 보장, 추천, 매수·매도 권유, "수익 극대화" 등.

## 3. 자세한 설명 (Play 4,000자 / App Store 설명)

```
가족연금계획은 내가 직접 입력한 연금·배당 보유 내역을 한곳에 모아 보여 주는 기록·계산 도구입니다.
증권사 계좌와 연결하지 않고, 매매나 자문도 하지 않습니다. 앱에 보이는 숫자는 모두 내가 입력한 값을 바탕으로 계산한 참고 자료입니다.

■ 이런 화면이 있습니다
• 홈 — 총 평가금액, 총 손익과 수익률, 은퇴 목표 월 현금흐름 대비 진행률, 자산군별 비중을 한눈에 봅니다.
• 자산 — 보유 종목별 평가금액, 손익, 전체 대비 비중을 목록으로 확인합니다.
• 배당 — 지금까지 받은 배당, 예상 연 배당, 월별 흐름, 예정된 배당 일정을 봅니다.
• 연금 — 연금계좌 납입, 연금 소득원, 은퇴 목표, 세액공제 납입 진행률, 은퇴 시점 예상 월 현금흐름을 요약해 봅니다(읽기 전용, 입력한 값과 화면에 적힌 계산 가정에 따른 참고 자료).
• 기록 입력 — 이미 한 매수와 이미 받은 배당을 앱에서 기록합니다. 주문이 실행되지는 않습니다. 매수 기록과 배당 수령 기록은 앱에서 한 건씩 삭제할 수 있습니다. 매수 기록을 삭제하면 그 기록이 더했던 보유 수량과 원가가 되돌아가며, 되돌릴 수 없는 경우에는 삭제되지 않고 안내가 표시됩니다.
• 계좌 전환 — 가족 계좌(본인·배우자·자녀)가 여러 개면 칩으로 골라 계좌별로 봅니다.
• 설정 — 비밀번호 변경, 로그아웃, 개인정보처리방침, 계정 삭제 안내, 계정 삭제를 앱 안에서 할 수 있습니다.

■ 웹 서비스와 함께 쓰는 앱
보유 종목 편집, 은퇴 목표, 연금 소득원 같은 입력은 가족연금계획 웹 서비스에서 합니다. 같은 이메일 계정으로 앱에 로그인하면 입력한 내용을 앱에서 조회할 수 있습니다. (웹에서는 연금 납입 기록, 자녀 증여 기록 등도 관리합니다.)

■ 이용 안내
• 이메일과 비밀번호로 가입합니다.
• 앱 안에서 언제든 계정과 저장된 데이터를 삭제할 수 있습니다. (설정 → 계정 삭제)
• 광고가 없습니다.
• 이 앱은 투자 권유, 투자 자문, 중개, 자금 예치를 하지 않습니다. 매수 기록은 이미 한 거래를 적는 것이며 주문이 실행되지 않습니다. 표시되는 평가금액과 수익률은 입력값과 외부 시세에 따라 달라지며 실제 계좌와 다를 수 있습니다. 투자 판단과 책임은 이용자 본인에게 있습니다.

문의: NEXT_PUBLIC_SUPPORT_EMAIL
개인정보처리방침: {웹 주소}/privacy
계정 삭제 안내: {웹 주소}/account-deletion
```

- `{웹 주소}`는 배포 도메인 확정 후 채웁니다. 현재 EAS 설정의 API 주소는 `https://economic-freedom.vercel.app`(`mobile/eas.json`)이며, 스토어 제출 전 최종 도메인 확인이 필요합니다. **확인 필요**
- "시세"를 언급한 이유: 웹 서비스가 네이버·야후 등에서 시세를 가져옵니다(`data-safety.md` 참고). 앱 화면의 현재가가 실시간이라고는 쓰지 않았습니다.
- 웹에만 있고 모바일에 없는 기능(연금 설계 입력, 자녀 증여, 적립 배분 계산(옛 '매수 계획'), ETF 비교, 시장 현황, 텔레그램 리포트)은 모바일 스토어 설명에서 주기능으로 내세우지 않았습니다. 웹 기능을 언급하려면 "웹 서비스에서"라고 명시해야 합니다. 연금 설계는 모바일에서 읽기 전용 요약만 있습니다.
- 텔레그램 기능은 웹 전용이라 앱 설명에서 **의도적으로 제외**했습니다(`mobile/src`에 텔레그램 코드 없음). 웹에서는 설정 > 텔레그램 연결에서 연결 코드를 발급받아 봇에 보내 본인 채팅임을 확인한 뒤에만 리포트가 가며, 해제도 웹 설정에서 합니다(PR #41). 이용자가 chat_id를 직접 입력하던 방식은 없어졌으므로, 웹 기능을 소개하는 문구를 쓸 때 "chat_id 입력" 같은 표현을 쓰지 마세요. 봇·AI 요약(`src/app/api/telegram-bot`, `cron/*`)은 운영자 전용이고, 현재 코드는 웹훅 시크릿이 없거나 허용 chat_id에 없으면 질문에 답하지 않으며, 프롬프트는 정보 정리이며 AI가 만든 메시지에 고지 문구가 붙습니다(`src/lib/ai-text.ts`). 봇·AI 요약은 모바일 앱 기능이 아니라 운영자 전용 기능이므로 설명에 넣지 않았고, `review-notes.md`에 상태를 적었습니다.

## 6. 스크린샷 구성안

모바일 앱 화면 기준, 이 순서를 제안합니다. 데모 계정(`review-notes.md`)에 **가상 데이터**를 넣어 촬영하고 실제 개인 자산 값을 쓰지 않습니다.

| 순서 | 화면 | 강조 문구 예시(화면 면적 20% 이내) |
|---|---|---|
| 1 | 홈 — 총 평가금액·손익·은퇴 현금흐름 진행률 (`(tabs)/index.tsx`) | 내 연금·배당 현황을 한눈에 |
| 2 | 홈 하단 — 자산 구성 비중 | 자산군별 비중 확인 |
| 3 | 자산 탭 — 보유 종목 목록 (`(tabs)/holdings.tsx`) | 종목별 평가금액과 손익 |
| 4 | 배당 탭 — 예상 연 배당·월별 흐름 (`(tabs)/dividends.tsx`) | 월별 배당 현금흐름 |
| 5 | 배당 탭 하단 — 예정 캘린더 | 예정된 배당 일정 |
| 6 | 연금 탭 — 납입·소득원·은퇴 시점 예상 현금흐름 (`(tabs)/retirement.tsx`) | 가족 연금 계획을 한 화면에서 |
| 7 | 매수 기록 추가·최근 기록 삭제 화면 (`record-purchase.tsx`) | 이미 한 거래를 기록하고 잘못 넣은 기록은 지움 (주문 없음) |
| 8 | 설정 탭 — 개인정보처리방침·계정 삭제 안내 링크 | 내 데이터는 내가 삭제 |

규격(공식 페이지 확인, 2026-11-27):
- Google Play: 휴대전화 스크린샷 2~8장, PNG/JPEG, 장당 8MB 이하, 변 길이 320~3,840px, 긴 변이 짧은 변의 2.3배 이하. 앱 아이콘 512×512 32비트 PNG, 피처 그래픽 1024×500. 추천 노출 조건으로 1080px 이상 4장 이상 권장. 출처: https://support.google.com/googleplay/android-developer/answer/9866151
- App Store: 기기 크기별 최대 10장, JPEG/PNG, 알파 채널 불가. 앱이 iPad를 지원하면(`mobile/app.json`의 `supportsTablet: true`) iPad 13인치 스크린샷 필요. 정확한 픽셀 크기는 페이지의 모델 요약 기준이라 **미확인(재확인 필요)**. 출처: https://developer.apple.com/help/app-store-connect/reference/screenshot-specifications
