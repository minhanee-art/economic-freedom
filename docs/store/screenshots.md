## 2. 현재 앱에 실제로 있는 화면

`mobile/src/app`: 하단 탭 5개 `홈 / 자산 / 배당 / 연금 / 설정`(`(tabs)/_layout.tsx`), 그리고 `login`, `signup`, `record-purchase`(매수 기록 추가·최근 기록 삭제), `record-dividend`(배당 수령 기록), `delete-account`. 계좌 전환 칩, 비밀번호 변경, 방침·삭제 안내 링크는 홈/설정 탭 안에 있음.
화면 제목 확인: 홈 '가족연금계획', 연금 '연금 설계', 설정 '설정', 매수 기록 '매수 기록 추가'.
**없는 화면(찍지 말 것)**: 보유 종목 편집, 은퇴 목표·연금 소득원 입력(웹 전용), 텔레그램 연결, ETF 비교, 시장 현황, 자녀 증여, 모바일 Google 로그인.

## 4. 규격 (확실한 것만)

- 확인한 공식 페이지(https://support.google.com/googleplay/android-developer/answer/9866151, 확인일 2026-11-27, `listing-ko.md` 에 기록): 휴대전화 스크린샷 2~8장, PNG 또는 JPEG, 장당 8MB 이하, 변 길이 320~3,840px, 긴 변이 짧은 변의 2.3배 이하. 피처 그래픽 1024×500, 앱 아이콘 512×512 32비트 PNG.
- 기존 파일은 1080×1920(9:16)이라 이 범위 안이지만 위 이유로 재촬영 대상입니다.
- 추천 노출 조건(해상도 1080px 이상 4장 이상 등), 가로 이미지·태블릿 이미지 요건, 캡션을 이미지에 합성했을 때의 정책: **Play Console 에서 확인**.
- App Store 용(iPad 포함)은 `checklist.md` B절을 따릅니다. 이 문서는 Play 휴대전화 기준입니다.

## 5. 촬영 방법

반드시 **예시 데이터**로 찍습니다. 실제 계정·실제 이메일·실제 금액·가족 이름은 스크린샷에 나오면 안 됩니다. 운영 서버·운영 DB 에는 접속하지 않습니다.

방법 A — 로컬 예시 환경(권장, 운영과 완전히 분리):
1. 준비: Docker 실행, 저장소 루트 `npm ci`, `mobile/` 에서 `npm ci`(`.npmrc` 적용). 자세한 사전 조건은 `mobile/e2e/README.md`.
2. 저장소 루트에서 `E2E_KEEP_UP=1 ./scripts/mobile-e2e/run.sh` — 일회용 Postgres, 더미 환경변수의 Next 서버, CORS 프록시, Expo web 을 띄웁니다. 스모크 테스트가 끝나면 서버를 **띄워 둔 채** 멈추고 `Expo: http://localhost:8461`(기본 포트, `E2E_EXPO_PORT` 로 변경)을 출력합니다. Enter 를 누르면 전부 정리됩니다.
3. 주의: 스모크 테스트는 마지막에 계정 삭제까지 하므로 **테스트가 만든 계정은 남아 있지 않습니다**. 띄워 둔 서버에서 화면을 찍으려면 앱에서 새로 가입(`/signup`)한 뒤 예시 데이터를 입력해야 합니다. 두 번째 계좌·보유 종목은 모바일에서 만들 수 없어 API 로 준비해야 하고, 은퇴 목표·연금 소득원은 웹 서비스 화면(로컬 Next 서버 `http://127.0.0.1:3461`)에서 입력합니다. 이 준비 절차를 자동화한 스크립트는 **없음**(직접 입력).
4. 브라우저는 개발자 도구의 기기 에뮬레이션(Pixel 7, 1080×2400 계열)으로 열고 스크린샷을 저장합니다. 해상도·비율 조정은 Play 규격 안에서(위 4절).
5. 웹 타깃(react-native-web)은 실기기와 폰트·안전 영역·탭바 아이콘이 다를 수 있습니다(`mobile/e2e/README.md` 의 '확인되지 않는 것'). 스토어 이미지는 가능하면 **실기기 또는 안드로이드 에뮬레이터**로 찍는 것을 권장합니다(웹 타깃 화면으로 충분한지는 사용자 판단).

방법 B — 실기기: EAS preview/production 빌드를 설치하고 **예시 계정**(신규 가입, 가상 보유 수량)으로 입력해 찍습니다. 계정은 `review-notes.md` 의 심사용 계정 방식과 같이 만듭니다.

예시 데이터 기준(제안): 종목 5~7개, 일부 마이너스 손익, 금액은 현실적인 범위, 배당 일정은 촬영일 이후 날짜, 이메일 `user@example.com`, 이름·계좌명은 '본인'·'배우자' 같은 일반 명칭. 실제 상품명은 쓸 수 있으나 특정 상품을 권하는 인상이 없도록 캡션에 상품명을 넣지 않습니다.
