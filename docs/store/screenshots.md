## 2. 현재 앱에 실제로 있는 화면

`mobile/src/app`: 하단 탭 5개 `홈 / 자산 / 배당 / 연금 / 설정`(`(tabs)/_layout.tsx`), 그리고 `login`, `signup`, `record-purchase`(매수 기록 추가·최근 기록 삭제), `record-dividend`(배당 수령 기록), `delete-account`. 계좌 전환 칩, 비밀번호 변경, 방침·삭제 안내 링크는 홈/설정 탭 안에 있음.
화면 제목 확인: 홈 '가족연금계획', 연금 '연금 설계', 설정 '설정', 매수 기록 '매수 기록 추가'.
**없는 화면(찍지 말 것)**: 보유 종목 편집, 은퇴 목표·연금 소득원 입력(웹 전용), 텔레그램 연결, ETF 비교, 시장 현황, 자녀 증여, 모바일 Google 로그인.

## 4. 규격 (확실한 것만)

- 확인한 공식 페이지(https://support.google.com/googleplay/android-developer/answer/9866151, 확인일 2026-11-27, `listing-ko.md` 에 기록): 휴대전화 스크린샷 2~8장, PNG 또는 JPEG, 장당 8MB 이하, 변 길이 320~3,840px, 긴 변이 짧은 변의 2.3배 이하. 피처 그래픽 1024×500, 앱 아이콘 512×512 32비트 PNG.
- 기존 파일은 1080×1920(9:16)이라 이 범위 안이지만 위 이유로 재촬영 대상입니다.
- 추천 노출 조건(해상도 1080px 이상 4장 이상 등), 가로 이미지·태블릿 이미지 요건, 캡션을 이미지에 합성했을 때의 정책: **Play Console 에서 확인**.
- App Store 용(iPad 포함)은 `checklist.md` B절을 따릅니다. 이 문서는 Play 휴대전화 기준입니다.

## 5. 촬영 방법

반드시 **예시 데이터**로 찍습니다. 실제 계정·실제 이메일·실제 금액·가족 이름은 스크린샷에 나오면 안 됩니다. 운영 서버·운영 DB 에는 접속하지 않습니다.

방법 A — 로컬 예시 환경, 스크립트로 재현(권장, 운영과 완전히 분리). 사전 조건은 `mobile/e2e/README.md`(Docker, 루트 `npm ci`, `mobile/` `npm ci`):

```bash
E2E_SCRIPT=screenshots.mjs E2E_SCREENSHOT_DIR=/home/minhanee/projects/pension-manager/mobile/store-assets/2026-11-27 ./scripts/mobile-e2e/run.sh
```

- 포트가 겹치면 `E2E_DB_PORT`·`E2E_NEXT_PORT`·`E2E_PROXY_PORT`·`E2E_EXPO_PORT` 를 지정합니다(다른 스모크 실행과 동시에 돌릴 때).
- `E2E_SCRIPT` 를 생략하면 기존 스모크(`smoke.mjs`)가 돕니다. `mobile/e2e/screenshots.mjs` 가 일회용 DB·서버를 띄운 환경에서 예시 계정(`user@example.com`)으로 가입하고, API 로 예시 데이터를 넣은 뒤 8개 화면을 찍습니다.
- 예시 데이터: 계좌 4개(내 계좌·배우자 계좌·내 연금저축·배우자 IRP), 내 계좌 종목 5개(일부 평가손실)와 매수 기록 9건·올해 배당 수령 기록·촬영일 이후 배당 일정 5건, 배우자 계좌 종목 2개, 올해 연금 납입, 은퇴 목표(목표 월 생활비·은퇴 나이·출생연도·본인/배우자 총급여 구간), 연금 소득원 3건. 시세는 외부 호출 없이 `current_price` 를 직접 넣습니다. 날짜는 촬영일 기준으로 계산합니다.
- 산출물(`E2E_SCREENSHOT_DIR` 아래, 1080×1920 PNG, 폰 뷰포트 한 화면 — 하단 탭바 포함, 전체 페이지 아님):
  - `raw/phone-0N-*.png` 앱 화면 원본 8장
  - `captioned/phone-0N-*-captioned.png` 위 3절 표의 '상단 캡션(안)'을 얹은 스토어용 8장(배경·글자색은 `mobile/src/styles/theme.ts` 색, HTML 을 Playwright 로 렌더링해 합성)
  - `capture-info.json` 촬영 설정·캡션 목록. 두 폴더는 `.gitignore`(`mobile/store-assets/`) 대상이라 커밋되지 않습니다. 기존 `phone-01~04` 등 파일은 건드리지 않습니다.
- 8장 구성: 1 홈 / 2 자산 / 3 배당 / 4 연금(명의자별 공제액·은퇴 시점 현금흐름) / 5 매수 기록 추가(입력 후 기록 금액) / 6 최근 매수 기록 목록 / 7 배당 수령 기록 / 8 설정. 5·7번은 종목이 2개인 배우자 계좌 화면이라 안내문·입력·기록 금액이 한 화면에 들어옵니다. 6번은 기록이 많은 내 계좌입니다.

**이 방법의 한계(웹 타깃 촬영)**
- 화면은 Expo web(react-native-web)+Chromium 입니다. **실기기와 글꼴(웹은 시스템 한글 글꼴), 안전 영역, 탭 아이콘(웹은 Material Symbols 글꼴)이 다를 수 있습니다.** 실기기·안드로이드 에뮬레이터로 다시 찍을지는 **사용자 판단**(스토어 이미지가 실제 앱과 다르게 보이면 안 되는 쪽이 안전합니다).
- **6번 '삭제 확인 창'은 찍히지 않습니다.** 웹 타깃의 확인 창은 브라우저 `confirm` 대화상자라 화면 캡처에 들어오지 않아, 삭제 버튼이 보이는 '최근 매수 기록' 목록 상태로 찍었습니다. 확인 창 문구("보유 수량과 원가가 되돌아갑니다")를 보여 주려면 실기기·에뮬레이터 촬영이 필요합니다.
- 캡션 합성은 폰 프레임 목업이 아니라 둥근 모서리 화면을 띠 아래에 놓는 단순 레이아웃입니다. Play 가 캡션 합성 이미지에 요구하는 정책은 4절대로 **Play Console 에서 확인**.
- 숫자는 모두 예시이며 실제 상품 시세와 무관합니다. 종목명은 실제 ETF 이름이지만 캡션에는 상품명을 쓰지 않았습니다.

방법 B — 실기기: EAS preview/production 빌드를 설치하고 **예시 계정**(신규 가입, 가상 보유 수량)으로 입력해 찍습니다. 계정은 `review-notes.md` 의 심사용 계정 방식과 같이 만듭니다.

예시 데이터 기준: 종목 5~7개, 일부 마이너스 손익, 금액은 현실적인 범위, 배당 일정은 촬영일 이후 날짜, 이메일 `user@example.com`, 이름·계좌명은 '본인'·'배우자' 같은 일반 명칭. 실제 상품명은 쓸 수 있으나 특정 상품을 권하는 인상이 없도록 캡션에 상품명을 넣지 않습니다.
